# 시은이 영어 단어 연습

초등 4학년이 주 3회(월·수·금) 치르는 영단어 시험을 준비하는 학습 웹앱.
단어장 사진을 찍으면 파닉스 규칙 추출 → 덩어리 읽기 → 시험 → 오답 복습 → 최종 시험까지 자동으로 이어진다.

---

## 1. 왜 만드는가

### 관찰된 문제

30개 단어를 놓고 시험을 봤을 때 나온 실제 오답이다.

| 정답 | 아이가 쓴 답 | 읽히는 원인 |
|---|---|---|
| strength | Straning | 앞 3글자만 맞고 뒤 붕괴 |
| recognize | Coregth | 첫 글자 틀림 + 직전 단어 조각(-th) 혼입 |
| bullet | Bullth | 앞 4글자 맞음, 끝 -th 혼입 |
| insert | Insout | 힌트의 시작 글자를 무시 |
| scissors | Scissers | 끝 -ors → -ers |
| coral reef | Crowed reef | 뒷단어만 정답 |
| amazing | Amaging | z → g |
| vision | Visien | -ion → -ien |
| creature | Creater | -ture의 u 누락 |
| fascinating | Fasounating | 묵음 c 누락 |

공통점이 뚜렷하다.

1. **앞부분은 맞고 뒤로 갈수록 무너진다** — 소리를 철자로 바꾸는 규칙이 없어서 단어를 사진처럼 통째로 외운다.
2. **직전에 본 단어의 조각이 섞여 들어온다** — strength의 `-th`가 뒤이어 recognize, bullet에 연달아 나타났다.
3. **읽기와 외우기가 따로가 아니다** — 못 읽으니 못 외운다. 순수 암기로 30개는 감당이 안 된다.

### 검증된 가설

같은 아이, 같은 30개 단어인데 **힌트 방식만 바꾸자 결과가 뒤집혔다.**

| 방식 | 결과 |
|---|---|
| 발음기호 + 음절 수만 제시 | 15문제 중 3개 정답 |
| 덩어리 분리 + 마스크 힌트 + 연상 요령 | 30문제 중 19개 정답 |

`material`은 "몰라"였다가 `ma-te-ri-al` 네 덩어리로 끊어주자 바로 맞혔다.
`wound`, `swallow`, `coral reef`, `bullet`, `scissors`는 1차에서 틀렸다가 2차에서 전부 맞혔다.

**이 앱은 그 방식을 자동화한 것이다.** 새 기능을 발명하는 게 아니라, 손으로 하면 30분 걸리는 준비를 사진 한 장으로 끝내는 게 목표다.

### 사용자

- **주 사용자**: 초4 딸. 혼자서 끝까지 돌 수 있어야 한다. 설명 없이 다음 버튼이 어디인지 알아야 한다.
- **보조 사용자**: 아빠(개발자). 사진 등록, 추출 결과 검수, 진척 확인.

## 2. 화면 흐름

```
[1] 사진 올리기
     ↓  단어·뜻·발음덩어리 추출 + 파닉스 규칙 5개
[2] 파닉스 — 규칙별로 해당 단어를 묶어 보여줌, 패턴 부분 형광 표시
     ↓
[3] 덩어리 읽기 — 단어를 덩어리로 쪼개 보여주고 소리 재생. 단어마다 연상 한 줄
     ↓
[3-2] 덩어리 맞추기 — 뜻을 보고 섞인 덩어리 칩을 순서대로 눌러 단어를 만든다 (연습, 채점 없음)
     ↓
[3-3] 이야기 — 오늘 단어가 섞인 짧은 한국어 이야기. 영어 단어를 누르면 소리 (재미, 시험과 무관)
     ↓
[4] 1차 시험 — 3가지 유형 순환 출제
     ↓
[5] 오답 복습 — 틀린 것만 (전부 맞히면 자동 건너뜀)
     ↓
[6] 최종 시험 — 전체 단어를 순서 바꿔 다시
```

### 문제 유형 3가지

학교 시험이 이 세 형태로 나오므로 그대로 맞춘다.

| type | 문제 | 답 입력 |
|---|---|---|
| `spell` | 한글 뜻 제시 | 영어 철자 입력 |
| `listen` | 음성 재생만 | 영어 철자 입력 |
| `meaning` | 영어 단어 제시 | 한글 뜻 4지선다 |

`meaning`을 객관식으로 둔 이유: 초4에게 한글 뜻을 타이핑시키면 채점이 부정확해지고(`시력` vs `시력, 눈`) 입력 부담이 크다. 오답 보기는 같은 단어장 안의 다른 뜻에서 뽑는다.

유형은 `types[i % types.length]`로 순환 배정한다. 랜덤 배정하면 한쪽으로 쏠려서 받아쓰기가 하나도 안 나오는 회차가 생긴다.

## 3. 핵심 기능

### 3.1 덩어리 칩 (이 앱의 중심 장치)

단어를 발음 덩어리로 쪼개 칩으로 표시하고, 인접한 칩은 배경색을 번갈아 칠한다.

```
[ma][te][ri][al]     ← 색이 교대로 바뀌어 경계가 눈에 보임
```

- **칩을 누르면 그 덩어리만 소리가 난다.** 단어 전체를 반복해 듣는 것보다 효과가 크다.
- 파닉스 화면에서는 해당 패턴에 걸리는 칩만 형광 처리한다.
- 덩어리는 추출 시 함께 생성한다. 영어 음절 분리는 규칙 기반으로 정확히 짜기 어려워 LLM에 맡기고, 이어붙인 결과가 원본 철자와 다르면 통째로 되돌린다(`sanitizeWords`).

### 3.2 마스크 힌트

`hintMask(word)` — 첫 글자, 마지막 글자, 3의 배수 위치만 남기고 나머지를 `_`로 가린다.

```
coral    → c _ _ a l
material → m _ _ e _ _ a l
```

첫 글자와 끝 글자를 항상 보여주는 게 중요하다. 아이가 `insert`를 `Sent`라고 쓴 건 시작 글자를 몰라서였다.

### 3.3 부분 정답 피드백

`commonPrefixLen`으로 앞에서 몇 글자가 맞았는지 세어 알려준다.

> "앞의 4글자는 맞았어요. 뒷부분만 다시 보면 돼요."

오답의 대부분이 "앞은 맞고 뒤가 틀림" 형태라 이 피드백이 실제로 잘 먹혔다. 틀렸다고만 하면 전부 다시 외워야 할 것처럼 느낀다.

### 3.3-2 덩어리 맞추기 · 연상 한 줄 · 이야기

검증된 방식(덩어리 + 마스크 힌트 + 연상 요령)을 더 밀어주는 세 장치. 게이미피케이션은 아니다(§8).

- **덩어리 맞추기** (`shared/assembly.mjs`): 덩어리가 2개 이상인 단어만 낸다. 섞인 칩을 순서대로 누르면 그 덩어리 소리가 나고, 다 채우면 바로 맞춘다. 틀리면 "앞의 2덩어리는 맞았어요" 하고 다시 맞출 수 있다. 시험이 아니라 연습이라 결과는 남기지 않는다. 타이핑이 없어 한/영 전환 부담이 없다
- **연상 한 줄**: 파닉스 규칙을 뽑을 때 단어마다 소리와 뜻을 잇는 우스운 한 문장을 함께 받는다(`mnemonics`). 덩어리 읽기 화면과 시험 정답 확인에 뜬다
- **이야기** (`/api/extract/story`): 단어 5~8개가 영어 철자 그대로 들어간 한국어 3~4문장. 영어 단어는 칩으로 보이고 누르면 소리, "이야기 듣기"는 한국어 목소리로 읽는다. 단어가 2개 미만 들어가면 한 번 다시 만들고, 그래도 안 되면 건너뛴다. 단어장당 1회 호출이고 단어장에 저장된다

### 3.4 음성

브라우저 `speechSynthesis`. 별도 비용이 들지 않고 오프라인에서도 동작한다.

- 기본 `rate = 0.8`, "천천히" 버튼은 `0.5`
- `lang = 'en-US'`, 목소리는 `en-US` → `en*` 순으로 폴백

**주의점은 §7에 따로 정리했다. 여기서 제일 많이 깨진다.**

### 3.5 오답 누적

한 세션 안에서는 1차 → 오답 → 최종으로 이어진다.
서버로 옮기면 회차를 넘어 누적해야 한다. **여러 주에 걸쳐 계속 틀리는 단어**를 뽑아내는 게 장기적으로 가장 값어치 있는 데이터다.

### 사진 없이 직접 넣기 · 단계 이동

- 사진 화면의 "사진 없이 직접 넣기"로 검수 표에 바로 적거나 여러 줄을 붙여 넣어 단어장을 만든다. 한 줄에 `crea-ture 생명체` 처럼 쓰면 `-` 가 덩어리 경계가 되고, 앞 번호(`03`)와 품사 표시(`n.`)는 자동으로 뗀다 (`shared/manual-entry.mjs`). 사진 추출 비용이 들지 않고 파닉스·이야기만 호출한다
- 상단 단계 번호를 누르면 그 단계로 바로 간다. 시험·오답·최종은 새 문제지로 다시 시작하고, 오답은 틀린 단어가 있을 때만 눌린다. 사진을 누르면 처음으로 돌아가며 단어장은 목록에 남아 있다

### 추출 결과 검수 화면 (§6.1) 이 들어 있다

추출 직후, 저장 전에 단어/뜻/덩어리 표가 뜬다. 칸을 눌러 바로 고치고, 줄을 지우거나 추가할 수 있다.
다음 항목은 노란 줄로 표시한다: 뜻이 비었거나 한 글자, 같은 뜻이 두 단어에 붙음, 덩어리가 안 나뉜 긴 단어, 덩어리를 이어붙이면 단어와 다름.
빈 칸이 남아 있으면 시작 버튼이 막힌다.

### 서버 함수가 하는 일 (CLAUDE.md 의 4단계)

1. `stop_reason === 'max_tokens'` 면 같은 사진을 "위쪽 절반만" / "아래쪽 절반만" 으로 두 번 다시 물어 합친다
2. JSON 파싱 실패 → `extractJson` 으로 복구, 그래도 안 되면 한 번만 재시도
3. `sanitizeWords` 로 빈 단어·중복 제거. 뜻이 빈 항목은 검수 화면에 띄우기 위해 남긴다
4. `chunks` 를 이어붙여 철자가 다르면 통째로 `[word]` 로 되돌린다

응답은 `output_config.format` 으로 JSON 스키마를 강제하지만, 위 네 단계는 그와 별개로 항상 돈다.
`stop_reason === 'refusal'` 이면 재시도하지 않고 다시 찍으라고 안내한다.

### 저장

DB 는 쓰지 않는다. 두 겹으로 저장한다.

- **이 기기**: 브라우저 `localStorage` 에 최근 20개(`src/storage.js`). 사진 화면 아래 "지난 단어장" 목록에서 이어서 한다. 순서와 잘라내기 기준은 "만들거나 이 기기에서 공부한 최근 시각"이라, 공유에서 받아 한 번 공부한 옛 단어장은 새 단어장에 밀려나지 않고 "이 기기에서 공부함"으로 표시된다
- **묶어서 시험**: 목록에서 여러 단어장을 골라 바로 1차 → 오답 → 최종. 같은 단어는 하나로, 규칙은 pattern 기준으로 합친다(`combineWordSets`). 저장하지 않고 이야기도 새로 만들지 않는다
- **공유**: `GITHUB_TOKEN` 이 있으면 서버 함수가 이 저장소의 `data` 브랜치 `wordsets.json` 에 최근 5개를 커밋한다(`api/wordsets`, `api/_lib/github.mjs`). 앱을 열면 받아와 이 기기 목록과 합치고, 합칠 때 같은 단어장은 공유 쪽을 믿는다(`mergeWordSets`). 토큰이 없으면 이 겹은 조용히 꺼진다

목록 조작은 전부 `shared/wordsets.mjs` 의 순수 함수다. 회차를 넘는 오답 누적(§3.5)은 아직 없다. 필요해지면 같은 방식으로 `data` 브랜치에 파일을 하나 더 두거나 그때 DB 를 결정한다.

### 모델 비교

`scripts/compare-models.mjs` 가 같은 사진을 여러 모델에 넣어 추출 정확도(단어 재현, 뜻 일치, 덩어리 분리)·속도·비용을 비교하고, 파닉스·연상·이야기는 나란히 출력한다. 실제 앱과 같은 프롬프트와 4단계 검증을 쓴다.

```bash
node scripts/compare-models.mjs --models claude-opus-5,claude-sonnet-5,claude-haiku-4-5
```

- 사진은 `test_img/` (git 에 올라가지 않는다), 정답은 `test_img/answers.json` — 검수 화면에서 고친 최종 단어장을 그대로 쓴다
- 키는 `.env.local` 의 `ANTHROPIC_API_KEY`
- 결과는 콘솔 표와 `test_img/compare-<시각>.md`

### 아이콘·미리보기 이미지

`public/` 의 아이콘(favicon, 홈 화면 아이콘)과 링크 미리보기(`og.png`)는 `scripts/make-icons.py` 가 만든다. 디자인을 바꾸면 스크립트를 고치고 다시 실행한다. `og:image` 의 절대 주소는 빌드 때 `vite.config.js` 가 Vercel 의 배포 주소로 채운다. 검색 엔진에는 올리지 않는다(`noindex`).

## 5. 목표 아키텍처 (다음 단계)

현재 Vercel 함수 구조는 API 키 은닉과 검수 화면까지를 감당한다. 회차 누적(Attempt/AnswerLog/WeakWord)이 필요해지는 시점에 아래 구조로 옮긴다. `shared/` 의 순수 함수는 그대로 가져간다.

### NestJS 로 갈 경우

```
apps/
  api/                    NestJS
    src/
      extract/            사진 → 단어·파닉스 추출
      wordset/            단어장 CRUD
      quiz/               문제지 생성, 채점
      attempt/            시험 기록, 오답 누적
      shared/logic/       wordlab-logic 이식 (순수 함수)
  web/                    프론트엔드
```

### 데이터 모델

```
WordSet          id, title, createdAt, source(EP3A 등)
Word             id, wordSetId, word, meaning, chunks[], order
PhonicsRule      id, wordSetId, pattern, sound, tip, wordIds[]
Attempt          id, wordSetId, stage(quiz|review|final), seed,
                 startedAt, finishedAt, correctCount, totalCount
AnswerLog        id, attemptId, wordId, type, rawInput,
                 correct, matchedPrefixLen
WeakWord         wordId, missCount, lastMissedAt   ← 누적 오답
```

`AnswerLog.rawInput`을 반드시 남길 것. `Bullth`, `Insout` 같은 실제 오답 문자열이 다음 개선의 근거가 된다.

### API

| 메서드 | 경로 | 설명 |
|---|---|---|
| `POST` | `/api/extract` | 이미지(base64) 1장 → 단어 목록. **키 은닉 목적, 반드시 서버 경유** — 구현됨 |
| `POST` | `/api/extract/phonics` | 단어 목록 → 파닉스 규칙 5개 — 구현됨 |
| `POST` | `/wordsets` | 검수 완료된 단어장 저장 |
| `GET` | `/wordsets/:id` | 단어장 조회 |
| `PATCH` | `/wordsets/:id/words/:wordId` | 단어·뜻·덩어리 수정 (검수 화면용) |
| `POST` | `/quiz` | `{wordSetId, stage, seed}` → 문제지 |
| `POST` | `/attempts/:id/answers` | 답안 기록 |
| `GET` | `/wordsets/:id/weak` | 누적 오답 단어 |

### 추출 프롬프트 규격

**단어 추출** — 이미지 + 텍스트 블록, 응답은 JSON only

```json
{"words":[{"word":"creature","meaning":"생명체","chunks":["crea","ture"]}]}
```

- `meaning`은 책에 적힌 그대로 짧게, 품사 표시(`n.`, `v.`)는 제외
- `chunks`는 이어붙이면 `word`와 철자가 정확히 일치해야 함

**파닉스 추출** — 단어 목록 → 최대 5개

```json
{"phonics":[{"pattern":"-ture","letters":["ture"],"sound":"처","tip":"...","words":["creature"]}]}
```

- 목록에 2개 이상 해당되는 규칙을 우선. 맞는 단어가 없으면 5개 미만이어도 된다 ("정확히 5개"를 요구하면 모델이 관계없는 단어를 끼워 넣어 채운다)
- `letters`는 단어 안에서 확인할 글자 조각. `_`는 자음 하나(`a_e` = 매직 e)
- 서버는 `letters`가 실제로 들어 있지 않은 단어를 규칙에서 빼고, 남는 단어가 없는 규칙은 버린다 (`sanitizePhonics`)
- 화면의 형광 표시도 같은 `letters`로 계산한다 (`highlightChunks`)
- 규칙 하나 = 소리 하나. `sound`에 쉼표로 여러 소리가 적혔거나 `letters`가 3개를 넘으면 "블렌드"처럼 여러 규칙을 묶은 것으로 보고 버린다
- 파닉스 화면의 **규칙 다시 뽑기** 버튼은 단어 목록만 다시 보낸다. 사진은 다시 읽지 않으므로 규칙이 이상할 때 사진 재분석 비용 없이 다시 받을 수 있다
- `tip`은 초등학생에게 하는 한 문장

## 6. 착수 시 반드시 지킬 것

### 6.1 추출 결과 검수 화면 — 최우선 (구현됨, §4 참고)

**이게 없으면 앱을 쓰면 안 된다.** OCR이 뜻을 한두 개 틀리게 읽으면 아이가 틀린 답을 외우게 된다. 학습 앱에서 이건 없느니만 못한 결과다.

- 추출 직후, 저장 전에 단어/뜻/덩어리를 표에 띄우고 인라인 수정 가능하게
- 신뢰도 낮은 항목(뜻이 비었거나, chunks가 fallback으로 대체된 항목)을 시각적으로 표시
- 부모가 30초 안에 훑고 넘길 수 있어야 함

### 6.2 max_tokens 와 분할 (구현됨)

서버 함수는 `max_tokens: 8000`. 그래도 잘리면 같은 사진을 상반부/하반부 프롬프트로 나눠 다시 묻는다(이미지를 실제로 자르지는 않는다).

- 서버에서는 이미지당 처리하되, 잘림을 감지하면 상반부/하반부로 나눠 재시도
- `extractJson`은 중괄호 구간 복구만 하지 잘린 배열을 되살리진 못한다
- `stop_reason === 'max_tokens'`를 명시적으로 검사할 것

### 6.3 사진은 저장하지 않는다

교재 지면 사진이다. 추출이 끝나면 즉시 폐기하고 텍스트만 저장한다. 서버 디스크나 S3에 원본을 쌓아두지 말 것. 개인 학습 목적의 일시 처리 범위를 넘지 않게 유지한다.

### 6.4 테스트

순수 함수는 이미 29개 케이스가 있다. 이식하면서 다음을 추가한다.

- `POST /extract` — 응답이 잘렸을 때, JSON이 깨졌을 때, 단어가 0개일 때
- 채점 API — `Make Up` = `make up`, `makeup` ≠ `make up`
- 문제지 생성 — 같은 `seed`로 두 번 호출 시 동일한 결과
- 오답 누적 — 같은 단어를 3회 틀리면 `missCount === 3`

E2E는 "사진 업로드 → 검수 → 1차 → 오답 → 최종" 한 바퀴를 한 개만 둔다. 그 이상은 유지비가 더 크다.

## 7. 확인해야 할 것

### TTS 브라우저 편차 — 실제로 여기서 제일 많이 깨진다

| 항목 | 내용 |
|---|---|
| `getVoices()` 비동기 | 첫 호출 시 빈 배열이 오는 브라우저가 있다. `voiceschanged` 이벤트를 구독하고, 그래도 비면 목소리 지정 없이 재생 |
| iOS Safari | 사용자 제스처 없이는 재생되지 않는다. 화면 진입 시 자동 재생하는 구간(덩어리 읽기, 받아쓰기 첫 재생)이 조용히 실패할 수 있음 |
| 한국어 기기 | `en-US` 목소리가 아예 없을 수 있다. 이 경우 받아쓰기 유형 자체를 숨기거나 안내 문구를 띄울 것 |
| `cancel()` 타이밍 | 연속 재생 시 앞 음성이 잘린다. 프로토타입은 매번 `cancel()` 후 재생 |

**출시 전에 아이가 실제로 쓸 기기에서 반드시 확인할 것.** 태블릿인지 폰인지 노트북인지에 따라 결과가 다르다.

### 결정이 필요한 사항

- [ ] **아이가 쓸 기기가 무엇인가** — 위 TTS 확인의 전제이자, 입력창 크기·터치 영역 설계의 전제
- [ ] **영어 키보드 전환 부담** — 초4가 한/영 전환을 매끄럽게 하는가. 어려우면 화면 내 알파벳 키패드를 직접 만들어야 한다
- [ ] **한 회차 분량** — 30개를 한 번에 돌리면 1차+오답+최종에서 60문제 이상을 푼다. 15개씩 두 세트로 쪼갤지
- [ ] **로그인 필요 여부** — 로그인은 없다. 대신 `APP_PASSCODE` 환경변수를 넣으면 사진 추출에만 비밀번호를 요구한다(선택). 학습 화면은 서버를 부르지 않으므로 그대로 열린다
- [x] **호스팅** — Vercel. 절차는 `DEPLOY.md`
- [ ] **비용 상한** — 주 3회 × 사진 2~3장이면 미미하지만, 재시도 루프가 돌면 튄다. 일일 호출 상한을 걸 것

### 나중에 볼 것

- 누적 오답 기반 주차별 약점 리포트 (파닉스 규칙별 정답률)
- 예문 표시 — 프로토타입에서는 토큰 절약을 위해 뺐다. 시험에 예문이 나오지 않으므로 우선순위 낮음
- 발음 녹음 후 비교 — 재미 요소지만 정확도 확보가 어렵다

## 8. 만들지 말아야 할 것

기능을 늘리다 망하는 지점이 명확해서 적어둔다.

- **포인트·뱃지·랭킹** — 아이가 점수 올리기에 집중하면 오답 복습을 대충 넘긴다. 이 앱의 가치는 오답 반복에 있다
- **타이머·제한 시간** — 철자를 떠올리는 데 시간이 필요하다. 압박은 역효과
- **전체 단어 반복 학습** — 이미 맞힌 단어를 또 보는 데 시간을 쓰면 힘만 들고 늘지 않는다. 항상 오답만 돌린다
- **화려한 애니메이션** — 정답/오답 피드백 외의 모션은 산만하다
